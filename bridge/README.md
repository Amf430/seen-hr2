# جسر ZKTeco → Firestore

يقرأ البصمات من جهاز **MB1000/ID** على الشبكة المحلية ويرفعها إلى مجموعة
`zkAttendance` في Firestore.

> ⚠️ `zkAttendance` منفصلة تماماً عن `attendance` (تسجيل الموظف من جواله).
> لا يقفل أحدهما جلسة الآخر، والمسير يقرأ سجل الجهاز وحده.

---

## التشغيل على جهاز الشركة (ويندوز)

الترتيب مهمّ:

```
1. setup-power.bat        (كمسؤول)  — يمنع نوم الجهاز
2. install-service.bat    (كمسؤول)  — يثبّت الجسر كخدمة
```

المطلوب بجوار `zk_bridge.py`:

| الملف | من أين |
|---|---|
| `serviceAccountKey.json` | Firebase Console ← Project settings ← Service accounts ← Generate new private key |
| `nssm.exe` | https://nssm.cc/download |

والمكتبات:

```
pip install pyzk firebase-admin
```

> ⚠️ `serviceAccountKey.json` **لا يُرفع إلى git أبداً** — هو مفتاح كامل
> الصلاحية على قاعدة البيانات، يتجاوز كل قواعد الأمان. مُستثنى في
> `.gitignore`.

## لماذا كان يتوقّف «كل ما نام الجهاز»

ثلاثة أسباب متراكمة، عولجت كلها:

| السبب | العلاج |
|---|---|
| **نوم ويندوز** يُعلّق العملية ويُطفئ كرت الشبكة | `SetThreadExecutionState` داخل السكربت + `setup-power.bat` — طبقتان لأن سياسة المجموعة قد تتجاوز إحداهما |
| **`ommit_ping=False`** — pyzk يرسل ping قبل كل اتصال، وأجهزة ZKTeco كثيراً لا تردّ على ICMP وجدار ويندوز يحجبه، فيفشل رغم أن المنفذ 4370 مستجيب | `ommit_ping=True` — نجرّب الاتصال الحقيقي مباشرةً |
| **محاولة واحدة لكل دورة** — أي تعثّر لحظي يُسقط الدورة ويُظهر الجسر «منقطعاً» ثم ينجح بعد دقيقة | ٣ محاولات بفاصل ٥ ثوانٍ |

**تشغيل الجسر كخدمة لا يمنع النوم** — هذا سوء فهم شائع. الخدمة تحلّ
«يبدأ مع الإقلاع» و«يعيد تشغيل نفسه»، لا «يبقى الجهاز مستيقظاً».

ويبقى إعداد يدوي واحد لا يمكن أتمتته:

> Device Manager ← Network adapters ← [الكرت] ← Properties ← Power Management
> ← أزل **"Allow the computer to turn off this device to save power"**

بدونه قد يُطفأ كرت الشبكة وحده فينقطع الجسر والجهاز مستيقظ.

## الأوامر

```
python zk_bridge.py                 تشغيل عادي (حلقة مستمرة)
python zk_bridge.py --debug         اختبار: يطبع البصمات الخام بلا رفع  ← ابدأ بهذا
python zk_bridge.py --once          دورة واحدة ثم يخرج
python zk_bridge.py --reset         يصفّر المؤشّر (يعيد قراءة كل السجل)
python zk_bridge.py --reset --days 3   يرفع آخر 3 أيام فقط
```

`--debug` يفحص كل شيء دفعةً واحدة: الاتصال، عدد السجلات، **انحراف ساعة
الجهاز**، والأرقام الوظيفية غير المعرَّفة في النظام.

## إدارة الخدمة

```
sc query SeenZKBridge          الحالة
nssm stop   SeenZKBridge       إيقاف
nssm start  SeenZKBridge       تشغيل
nssm remove SeenZKBridge confirm   إزالة
```

السجل: `logs\bridge.log` (يُدوَّر عند 10 ميغا).

## التشخيص

لوحة الأدمن ← **سجل جهاز البصمة** تعرض بطاقة «حالة جسر البصمة»: آخر نبض،
نتيجة الاتصال، عدد السجلات، وآخر خطأ.

| العرَض | الغالب |
|---|---|
| «الجسر متوقّف» وآخر نبض قديم | الخدمة متوقّفة أو الجهاز نائم — راجع `logs\bridge.log` |
| `can't reach device (ping ...)` | نسخة قديمة بلا `ommit_ping=True` |
| `الاتصال نجح لكن السجل فارغ` | البصمة لم تُسجَّل على الجهاز أصلاً |
| بصمات لا تظهر رغم نجاح الاتصال | رقم وظيفي في الجهاز غير مطابق لحقل «الرقم الوظيفي» في النظام — يظهر في `--debug` |
| أوقات مزاحة بساعات | ساعة الجهاز خاطئة — يقيسها `--debug` |
